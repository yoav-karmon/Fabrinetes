# Gen Image Task Documentation

## Overview

The `gen_image` task is the modern image generation system that creates Docker images from TOML configuration files. It supports both base image creation and regular image generation with package installation via `docker exec`.

## Usage

```bash
# Generate image from config
./fabrinetes gen-image <config-file> [--dry-run] [--base-image]

# Show help
./fabrinetes gen-image
```

## Arguments

- `<config-file>`: Path to TOML config file (required)
- `--dry-run`: Show what would be generated without actually generating
- `--base-image`: Build base image from Dockerfile instead of creating new image

## Features

### Base Image Building (`--base-image`)
- Builds base images from Dockerfiles
- Handles build arguments (USERNAME, UID, GID, HOME_DIR)
- Saves base images as tarballs
- Supports restoration from tarballs

### Regular Image Generation
- Creates images from base images
- Installs packages via `docker exec`
- Supports both apt and Python packages
- Commits containers to new images
- Exports images as tarballs

### Package Management
- Reads package lists from `packages.txt`
- Installs packages one by one with progress reporting
- Handles both apt and pip packages
- Provides detailed installation logs

## Example Usage

```bash
# Build base image from Dockerfile
./fabrinetes gen-image containers/fabrinetes-dev-testing/config.toml --base-image

# Generate regular image with packages
./fabrinetes gen-image containers/fabrinetes-dev-testing/config.toml

# Dry run to see what would happen
./fabrinetes gen-image containers/fabrinetes-dev-testing/config.toml --dry-run
```

## Configuration Requirements

### Config File Structure
```toml
[config]
image_name = "container-name:tag"
base_image = "base-image:tag"
```

### Required Files
- `config.toml`: Container configuration
- `Dockerfile`: Base image definition (for base image building)
- `packages.txt`: Package list (for regular image generation)

## Process Flow

### Base Image Building
1. **Validation**: Check Dockerfile exists
2. **Build Arguments**: Set USERNAME, UID, GID, HOME_DIR
3. **Docker Build**: Build image from Dockerfile
4. **Tarball Export**: Save image as tarball
5. **Cleanup**: Report success

### Regular Image Generation
1. **Base Image Check**: Ensure base image is available
2. **Container Creation**: Start container from base image
3. **Package Installation**: Install packages via `docker exec`
4. **Image Commit**: Commit container to new image
5. **Tarball Export**: Save image as tarball
6. **Cleanup**: Remove temporary container

## Package Installation

### Package List Format
```
# Python packages
numpy
pandas
scipy

# Apt packages (if supported)
vim
git
curl
```

### Installation Process
1. **Package Parsing**: Read and parse package list
2. **Container Execution**: Use `docker exec` for installation
3. **Progress Reporting**: Show installation progress
4. **Error Handling**: Handle installation failures
5. **Verification**: Verify successful installation

## Integration

### With Other Tasks
- **run**: Uses images generated by gen_image
- **test**: Tests gen_image functionality
- **clean_image**: Cleans up generated images
- **commit**: Alternative to gen_image for modifications

### Docker Integration
- Uses `docker build` for base images
- Uses `docker exec` for package installation
- Uses `docker commit` for image creation
- Uses `docker save` for tarball export

## Error Handling

- **Missing Arguments**: Shows help if config file not provided
- **Config File Errors**: Handles TOML parsing errors
- **Dockerfile Missing**: Validates Dockerfile existence
- **Package Installation Failures**: Handles package errors
- **Build Failures**: Handles Docker build errors

## Troubleshooting

### Common Issues

1. **Config file not found**: Verify config file path
2. **Dockerfile missing**: Ensure Dockerfile exists for base image creation
3. **Package installation fails**: Check package names and availability
4. **Build fails**: Check Docker resources and permissions

### Debug Steps

1. Check config file: `cat <config-file>`
2. Verify Dockerfile: `ls <config-dir>/Dockerfile`
3. Check package list: `cat <config-dir>/packages.txt`
4. Test Docker build: `docker build <config-dir>`

## Best Practices

1. **Use descriptive image names** in config files
2. **Keep package lists minimal** for faster image creation
3. **Test base images** before creating regular images
4. **Use dry-run** to verify configuration
5. **Regular cleanup** of unused images

## Advanced Usage

### Custom Build Arguments
The base image building supports custom build arguments:
- `USERNAME`: User name for the container
- `UID`: User ID for the container
- `GID`: Group ID for the container
- `HOME_DIR`: Home directory path

### Package Management
- **Python packages**: Installed via pip
- **System packages**: Installed via apt (if supported)
- **Custom packages**: Can be added to package list

### Tarball Management
- **Automatic export**: Images are automatically saved as tarballs
- **Restoration support**: Tarballs can be restored later
- **Storage location**: Tarballs stored in `containers/<name>/`

## Safety Features

- **Validation**: Ensures all required files exist
- **Error Recovery**: Continues process even if some steps fail
- **Resource Management**: Handles Docker resource constraints
- **Cleanup**: Removes temporary containers and resources
- **Logging**: Provides detailed output for troubleshooting
