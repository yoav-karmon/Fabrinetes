## Documentation Standards

### File Naming Conventions
- **README.md**: Main documentation for directories
- **doc/**: Documentation files in markdown format
- **command/**: Command-specific documentation
- **examples/**: Example project documentation

### Content Standards
- **Markdown Format**: All documentation in Markdown (.md) format
- **Consistent Structure**: Headers, code blocks, and formatting
- **Cross-References**: Links between related documentation
- **Examples**: Practical examples and usage patterns
- **Troubleshooting**: Common issues and solutions

### Maintenance Guidelines
- **Keep Updated**: Documentation should reflect current code
- **Version Control**: All documentation in version control
- **Review Process**: Documentation changes should be reviewed
- **User Feedback**: Incorporate user feedback and questions

## Contributing to Documentation

### Adding New Documentation
1. **Determine Category**: Place in appropriate directory (`doc/`, `command/`, `examples/`)
2. **Follow Standards**: Use consistent naming and formatting
3. **Cross-Reference**: Link to related documentation
4. **Update Index**: Update this index file when adding new documentation

### Updating Existing Documentation
1. **Maintain Structure**: Keep existing structure and formatting
2. **Update Cross-References**: Update links when moving or renaming files
3. **Version Information**: Include version information for significant changes
4. **Review Process**: Follow same review process as code changes

### Documentation Review Checklist
- [ ] Content is accurate and up-to-date
- [ ] Formatting is consistent with project standards
- [ ] Cross-references are correct and working
- [ ] Examples are tested and functional
- [ ] Language is clear and accessible
- [ ] Structure is logical and easy to follow
